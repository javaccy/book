# 局域网两台 PC 互控 —— Sunshine + Moonlight（Hyprland/Wayland）

> 选型同《TCL电视投屏.md》：Sunshine（推流端）+ Moonlight（客户端），走硬件编码，带声音。
> 日期：2026-10-07 配置完成，两个方向均已实测串流通过

## 两台机器

| 机器 | hostname | IP | 显卡 / 显示器 | 防火墙 |
|------|----------|----|----------------|--------|
| 台式机 | archlinux | 192.168.144.230 | Intel 核显（iHD）/ HDMI-A-1 34" | nftables enabled |
| 笔记本 | yancc-arcolinux | 192.168.144.186 | AMD Phoenix / eDP-1 + DP-1 | 没开 |

两台都是 Arch/Arco + **Hyprland 0.56.2**（Wayland，Lua 配置 `~/.config/hypr/hyprland.lua`），互为推流端和客户端。
Sunshine 一次只推**一个**显示器（默认取合成器当前输出）。

## 一、推流端（两台都配好了）

```bash
yay -S sunshine-bin            # 预编译包
```

`~/.config/sunshine/sunshine.conf`：

```ini
capture = wlr
```

必须写死截屏方式，否则 Sunshine 启动即假死（Web UI 都起不来）：`xdg-desktop-portal-hyprland`
不支持 RemoteDesktop 接口，自动模式会卡在 portalgrab 初始化；`wlr` 走 Hyprland 原生支持的
wlr-screencopy 协议。

### 踩坑：台式机必须禁用 HEVC / AV1

**现象**：任何客户端发起串流约 1 秒后 Sunshine 直接 SIGABRT，systemd 反复重启
（`journalctl --user -u app-dev.lizardbyte.app.Sunshine.service` 里
`Main process exited, code=dumped, status=6/ABRT`，堆栈落在主串流线程的 `abort()`；
今早投 TCL 电视也是同一个原因，`NRestarts` 一度到了 7）。

**定位**：编码器建好后崩，日志停在 `Creating encoder [hevc_vaapi]` →
`vaapi vendor: Intel iHD driver ... 26.3.5` → `Minimum FPS target set to ~30fps`。
换 `--video-codec H.264` 就完全正常（还能看到 `Setting default sink to: [sink-sunshine-stereo]`
和 Opus 音频初始化）——是 Intel iHD 驱动下 hevc/av1 VAAPI 的问题，h264_vaapi 没事。

**处理**（台式机 `~/.config/sunshine/sunshine.conf`，改完重启服务）：

```ini
hevc_mode = 1   # 不对外宣告 HEVC
av1_mode  = 1   # 不对外宣告 AV1
```

客户端自动回落到 H.264，1080p60 够用。笔记本是 AMD，HEVC 正常，保持默认。

### 服务与自启

```bash
systemctl --user enable --now app-dev.lizardbyte.app.Sunshine.service
```

挂在 `graphical-session.target`，登录图形会话后自动起，监听 47984/47989/47990/48010。

### 输入注入（不用把自己加进 input 组）

```bash
ls -l /dev/uinput     # crw-rw----+ root input —— 末尾的 + 表示 uaccess ACL 已生效
```

`sunshine-bin` 自带 `/usr/lib/udev/rules.d/60-sunshine.rules`。

### 应用项：PC Remote Desktop

两台机器的 `~/.config/sunshine/apps.json` 都在**末尾**加了一条 `PC Remote Desktop`：

- 原有的 `Desktop` 带 prep-cmd `tv-mode.sh on`，串流开始会把主机屏切成 16:9（为投电视准备）。
- 从另一台 PC 远程进来时那会顺手改掉主机自己的分辨率，所以新增项**不带 prep-cmd**。
- 电视投屏流程不受影响：`tv-cast` 点的仍是网格第一张卡片 `Desktop`。

改完 apps.json 要 `systemctl --user restart app-dev.lizardbyte.app.Sunshine.service` 才生效。

## 二、客户端（Moonlight）

```bash
sudo pacman -S moonlight-qt     # extra 仓库
```

GUI 流程：打开 Moonlight → 局域网内 mDNS 自动发现主机卡片（也可以手填 IP）→ 点卡片 →
记下 4 位 PIN → 到主机的 https://<主机IP>:47990 填 PIN → 应用列表选 **PC Remote Desktop**。

### 命令行自动配对

Moonlight 6.2 支持自带 PIN：`moonlight pair <host> --pin 1234`。
新版 Sunshine 的接口要求 `pairing_id` + `name`，光发 pin 会 400：

```bash
curl -sk -u sunshine:sunshine123 https://192.168.144.186:47990/api/pin
# -> {"pairings":[{"id":"<32位hex>","name":"roth","address":"192.168.144.230"}]}
curl -sk -u sunshine:sunshine123 -X POST https://192.168.144.186:47990/api/pin \
  -H 'Content-Type: application/json' \
  -d '{"pairing_id":"<32位hex>","pin":"1234","name":"roth"}'
```

> 《TCL电视投屏.md》里老写法 `-d '{"pin":"..."}'` 在 2026.914 版 Sunshine 上会返回 400，
> 需要补 `pairing_id` 和 `name`。

## 三、pc-remote 一键脚本

两台的 `~/.local/bin/pc-remote`（源文件 `src/yancc/linux/scripts/pc-remote`），
自动识别对端 IP，把上面的配对流程包好了：

```bash
pc-remote pair            # 和对端配一次（写死 PIN，两端自动对齐；已配对会跳过）
pc-remote list            # 列出对端可串流的应用
pc-remote stream          # 直接开始串流（默认 PC Remote Desktop）
pc-remote gui             # 打开 Moonlight 图形界面
pc-remote peer            # 打印对端 IP
```

对端映射：台式机 → 192.168.144.186，笔记本 → 192.168.144.230。
可用 `PC_REMOTE_PEER` / `SUNSHINE_CREDS` 覆盖；SSH 里没有图形会话时脚本自动用
`QT_QPA_PLATFORM=offscreen`。

## 四、实测记录（2026-10-07）

| 方向 | 结果 |
|------|------|
| 笔记本 → 台式机 | ✅ 1920x1080x60 / H.264（台式机已禁用 HEVC、AV1）/ Opus 音频 / 100ms 收到首帧 / 主机 NRestarts=0 不崩 |
| 台式机 → 笔记本 | ✅ 1920x1080x60 / HEVC（AMD 硬编正常）/ Opus 音频 / 0ms 收到首帧 / 主机 NRestarts=0 不崩 |

两边都用 `grim` 截了串流画面确认：笔记本屏上显示的是台式机桌面，台式机屏上显示的是笔记本桌面。

两个观察：

- Moonlight 客户端会临时切换**客户端自己**的显示模式去匹配串流，断开后再恢复。
  台式机 HDMI-A-1 之前残留的 1080p，就是被它恢复回 3440x1440@30 的。
- 笔记本走 WiFi，串流时 Moonlight 报了 `Slow connection to PC`；画质吃紧就在 Moonlight 里降码率。

## 五、注意事项

- **换推流屏幕**：默认推当前输出。笔记本想推外接屏，`sunshine.conf` 加 `output_name = DP-1` 后重启服务。
- **鼠标指针**：Hyprland 0.56 的 `cursor:no_hardware_cursors` 默认 `2`（auto，抓屏时自动切软件光标），
  一般不用管；万一串流里看不到指针，设成 `1`。
- **音频**：走 PipeWire，串流主机侧临时出现虚拟 sink `sink-sunshine-stereo`（只在串流期间存在），
  客户端收到 Opus 48kHz 立体声。
- **主机崩了怎么查**：`journalctl --user -u app-dev.lizardbyte.app.Sunshine.service | grep -E 'dumped|exited'`。
- **台式机分辨率**：HDMI-A-1 原生 3440x1440 只有 30Hz（HDMI 带宽所限），日常就是这个模式。
  嫌远程桌面 30 帧不跟手，可以给 `PC Remote Desktop` 加 prep-cmd
  `/home/yancc/apps/tv/tv-mode.sh on`（串流期间切 1080p60，结束由 undo 恢复）。

## 六、故障排查：串流跑一会儿就掉线（Error code: -1）

**现象**：`pc-remote stream 192.168.144.186` 跑几十秒 ~ 2 分钟就断，Moonlight 弹
「Connection terminated / Error code: -1」，过程中还会闪「Slow connection to PC / Reduce your bitrate」。

**定位过程**（2026-10-07）：

1. 主机端没崩：笔记本 Sunshine `NRestarts=0`，日志只有 `CLIENT DISCONNECTED` —— 是客户端先断的。
2. 客户端日志：`Control stream received unexpected disconnect event` +
   `Loss Stats: Transaction failed`，并且大量 `Network dropped N frames` / `Unrecoverable frame`（**音频也在丢**）。
3. 网络裸测（1400 字节 UDP，python 手写收发，两台机器直接跑）：

   | 发送速率 | 丢包 |
   |----------|------|
   | 1 Mbps | 0% |
   | 5 Mbps | 0% |
   | 15 Mbps | 21% |
   | 30 Mbps | 61% |
   | 60 Mbps | 80% |

   接收侧稳定卡在 **~1040 包/秒（≈11.5 Mbps）**，换成精确节流也一样；
   MTU 1500、`ping -M do -s 1400` 都正常，排除 MTU 问题。
4. 同一对机器 **TCP 能跑 314 Mbps** —— 链路本身不慢，是 **UDP 被限速**。
5. 发送端（笔记本）驱动没丢包（`tx_dropped`/`tx_errors` 不变、`tx failed=0`），
   接收端（台式机）网卡 `rx_packets` 增量只有发送量的 ~60% ——
   **包是在中间（路由器/AP）被丢的**，不是两端防火墙、也不是网卡。

**结论**：局域网里的路由器/AP 对 UDP 有约 **1000 包/秒** 的限制（那台 `GL-KULUOBO`，
多半是「UDP 洪水防护 / 防攻击 / QoS」之类的设置）。而 Sunshine 按 1080p60 默认请求
15 Mbps ≈ 1340 包/秒，正好踩在限制之上，所以视频/音频丢包，最后控制流超时断开。

**处理**：

- `pc-remote` 已内置：**笔记本作主机时**默认 `--bitrate 8000`（实测 0 丢包、稳定不断），
  其它方向保持 Moonlight 自动码率。想改：`PC_REMOTE_BITRATE=15000 pc-remote stream 192.168.144.186`。
- 用图形界面连的时候要手动设：Moonlight → 该主机 → **Video bitrate 调到 8000 Kbps**（或更低），
  否则一样会掉。
- 想彻底解决得动路由器：翻「UDP flood protection / 防攻击 / QoS / SQM」相关设置，
  或者把笔记本接网线（有线方向实测 15 Mbps 不丢包）。
